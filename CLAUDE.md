# CLAUDE.md — LeadFlow AI

Lead Intelligence & Consultancy Operating System ("VertiCore MetaOS"),
built for education/career/medical-admission consultancies.

## Where things live

| Folder | Stack |
|---|---|
| `backend/` | Node.js + Express API, Postgres via Supabase (`backend/db.js`), 60+ route files in `backend/routes/`, services in `backend/services/` |
| `mobile/` | Flutter app (Android + Web/PWA), `mobile/lib/` |
| `web/` | Next.js — see `web/AGENTS.md` (auto-generated by `next dev`, do not hand-edit) |
| `01_PROJECT_REGISTRY/` | Applied SQL fixes (e.g. RLS lockdowns) kept for audit trail |

AI calls go through `backend/services/aiProvider.js` (`generateJson()` —
Claude/Gemini/OpenRouter). WhatsApp via Cloud API webhook. Payments via
Razorpay/eSewa/Khalti.

## Continuity files — read these before starting work, don't re-derive them

- `NEXT_TASK.md` — what to do next and why. Start here when resuming.
- `IMPLEMENTATION_PROGRESS.md` — what's done, by feature/module.
- `DECISION_LOG.md` — why things were built the way they were.
- `TECH_DEBT.md` — known issues not yet addressed.
- `ARCHITECTURE_MAP.md` — system diagram, route inventory.
- `FEATURE_STATUS.md` / `MODULES_STATUS.md` — feature-level status.

This project keeps continuity state as root-level Markdown files rather
than a `.project/` folder — don't create a parallel `.project/` system;
extend the files above instead.

## Working rules

- Don't scan the whole repo for a task — `NEXT_TASK.md` plus the 2-3 files
  a task actually touches is usually enough.
- Don't refactor or "clean up" code outside what the task requires.
- After a meaningful unit of work: update the relevant continuity file(s)
  above (usually `NEXT_TASK.md` and/or `IMPLEMENTATION_PROGRESS.md`), then
  commit. Don't push unless asked.
- Never commit `.env`, secrets, API keys, or credentials. CI/CD secrets
  live in GitHub Actions settings, not in the repo.
- CI: `.github/workflows/` runs build/release and scheduled jobs — check
  it stays green after backend or mobile changes that affect the build.
- Reusable workflow commands (`/project-status`, `/continue`, `/next`,
  `/audit`, `/checkpoint`, `/test`, `/handoff`, `/sync`, `/decisions`) are
  installed globally in `~/.claude/commands/` and work in any project,
  including this one — prefer them over re-deriving the same steps by
  hand. (Named to avoid colliding with Claude Code's built-in `/status`
  and `/resume`.)
